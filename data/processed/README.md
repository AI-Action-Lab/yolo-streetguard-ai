# Processed Dataset

## Overview

The `data/processed/` directory contains datasets generated by the preprocessing pipeline for YOLO StreetGuard AI.

The initial processed dataset contains road images and normalized YOLO bounding-box annotations for pothole detection.

These files are used for model training, validation, and testing.

## Directory Structure

```text
processed/
├── README.md
└── potholes/
    ├── data.yaml
    ├── images/
    │   ├── train/
    │   ├── val/
    │   └── test/
    └── labels/
        ├── train/
        ├── val/
        └── test/
```

The initial processed dataset contains:

| **Total** | **664** | **1,737** |

One invalid source annotation was excluded because its bounding box had zero width.

The dataset integrity checker reported zero structural or label-format issues.

## Directory Descriptions

### `potholes/images/`

Contains the image files organized into three subsets:

- `train/` — Images used to train the model.
- `val/` — Images used to monitor model performance and support model selection.
- `test/` — Images reserved for final evaluation.

### `potholes/labels/`

Contains YOLO annotation text files corresponding to the images.

Each annotation file contains the class identifier and normalized bounding-box coordinates for detected potholes.

### `potholes/data.yaml`

Defines the dataset configuration used by Ultralytics YOLO.

The configuration identifies the dataset path, training images, validation images, and object class names.

The current dataset has one class:

`0: pothole`

## YOLO Annotation Format

Each annotated object is represented by one line in a text file:

```text
class_id x_center y_center width height
```

The bounding-box coordinates are normalized relative to the image dimensions.

For the current dataset:

- `class_id` is `0`.
- `x_center` is the normalized horizontal center.
- `y_center` is the normalized vertical center.
- `width` is the normalized box width.
- `height` is the normalized box height.

The normalized coordinate values must be within the valid range from 0 to 1.

An image containing multiple annotated potholes can have multiple annotation lines.

An image without annotated objects may have an empty label file, depending on the dataset preparation workflow.

## Data Preprocessing

The dataset is generated by:

`src/data_processing/convert_voc_to_yolo.py`

The preprocessing script:

1. Reads the source images and Pascal VOC XML annotations.
2. Extracts bounding-box coordinates.
3. Checks whether the bounding boxes are valid.
4. Converts valid coordinates to normalized YOLO format.
5. Organizes images and labels into the appropriate subsets.
6. Generates the YOLO dataset configuration.

The conversion uses a fixed random seed of 42 when dividing the original training list into training and validation subsets.

## Dataset Validation

The generated dataset is checked using:

`src/data_processing/validate_yolo_dataset.py`

The validation process checks image and label correspondence, annotation formatting, and other structural requirements.

The initial validation results were:

| Check | Result |
|---|---|
| Training images | 479 |
| Validation images | 52 |
| Test images | 133 |
| Total images | 664 |
| Total bounding boxes | 1,737 |
| Structural or label-format issues | 0 |

## Training Configuration

The initial model training used a dataset configuration with the following split paths:

```yaml
train: images/train
val: images/val
test: images/test

names:
  0: pothole
```

The actual `data.yaml` also includes a dataset root path appropriate to the environment where training runs.

Dataset paths may need to be adjusted when moving between a local computer and Google Colab.

## Data Integrity Guidelines

- Do not manually modify generated labels without documenting the change.
- Rerun validation after changing annotations or dataset splits.
- Keep training, validation, and test data separate.
- Use validation data for iterative model improvements.
- Avoid repeatedly tuning the model against the test set.
- Regenerate the processed dataset when preprocessing logic changes.
- Do not commit large generated datasets unless explicitly required and permitted.

## Reproducibility

To recreate the processed dataset:

1. Obtain the authorized raw dataset.
2. Confirm that the expected source images, annotations, and split information are available.
3. Run the conversion script.
4. Review any excluded or invalid annotations.
5. Run the dataset-validation script.
6. Verify the output counts before starting training.
